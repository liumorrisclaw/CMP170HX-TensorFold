# 决策包：PP4-prefill 立项 vs TP4 定格转 lane rounds（2026-10-12）

> 背景：300 目标在 TP4 约束集内已被系统实验证伪（decode 实验矩阵 8 项全闭合，
> 241.5/181.6/117.0 = 实测全局最优，`0436adfa`）；prefill 1,551-1,588（7.8×），
> 剩余缺口 = 字节物理（TP4 每层全激活跨卡）。两案均已在 PLAN-AX300 定价。

## 案 A：PP4-prefill 立项（冲 prefill 2,000-3,000 + decode 架构重排）

**架构**：4 卡按层分 4 段（每段 ~11-12 层整权重），段间点对点传激活（一次/段边界
vs TP4 的 90 次/前向）。Morrowmake 实证：PP4 prefill 5,616 / TP4 1,017。

| 项 | 内容 |
|---|---|
| 显存 | 每卡 = 该段全宽权重（~40GB 级，与 TP4 相当）+ 段间缓冲 |
| 工作量 | 权重分段加载器、段间流水协议（p2p 或 host 中继）、KV/索引器的段归属、drafter 归属（末段）、serve 编排。**估 1-2 周** |
| 风险 | GLM 的 KDA/DSA 状态跨段语义（这是真正的硬骨头）；decode 侧 PP4 实测 107-217（劣于 TP4）→ 需 PP4-prefill + TP4-decode 双模式或混合 |
| 收益 | prefill 2,000-3,000（接近 Morrowmake 5,616 的下沿）；decode 架构前提解锁 |
| 验收门 | 冷 prefill ≥2,000；decode 不回归；exactness PASS（谱系新支，自洽） |

## 案 B：TP4 定格，转 lane rounds（聚合口径）

**架构**：并发请求共享解码轮次（上游 0.6.4 Flash Next 思想 + 自研）。

| 项 | 内容 |
|---|---|
| 收益 | 聚合吞吐 2-4×（Morrowmake c8 605-949 对照）；**单流 241 不变** |
| 工作量 | 轮次打包器 + KV slot 管理（已有 32,776 slots）+ 每请求深度。**估 3-5 天** |
| 风险 | 低（不改数值路径）；exactness 天然保持 |
| 适用 | 若"300"的本质是服务容量而非单流延迟 |

## 案 C：定格 241/1,550，工程转其他方向

收尾发布（公开仓 release、文档、runbook 定稿），300 作为 TP4 已证伪目标归档。

---

**我的建议**：若单流 300 是硬需求 → **案 A**（唯一路径，风险在 KDA/DSA 跨段）；
若服务容量是真实诉求 → **案 B**（便宜 3 倍、风险低、单流不损）。
