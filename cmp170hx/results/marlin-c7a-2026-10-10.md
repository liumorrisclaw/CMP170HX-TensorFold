## 因果链
1. **内核本身更快**：serial +18%（18.2ms vs 21.5ms/步）；coding +7.4%、prose +14.9%。
2. **对齐块 62µs 锚点是假象**：真实路由 R=8 时 72 个 pair 散布在 ~50-72 个不同专家 → 每层需读 50-72 个专家的权重 → DRAM 墙（~150-216MB/层）→ 与 affine 打平。**专家段的真实成本由 distinct-expert 数决定，与权重格式无关。**
3. **structured −24% 的根因 = 接受率下降，不是步时**：g128-requant 改变了目标 logits → DFlash2 drafter（对原始权重训练）接受率 ↓20%（tok/round 6.8→5.41）→ structured（高接受率画像）损失最大；coding/prose（低接受率画像）反而受益于更快的步。
4. **exactness FAIL 根因**：decode.cu 的 stripe split 依赖 tiles=blocks×N_TILES 与 pair 的 block index（取决于其他 token 的路由）→ 每 pair 的 fp32 累加顺序随 R 和路由分布变化 → 验证窗（R≥2）≠ serial（R=1）→ tie-break 翻转（第 41 token 分叉）。

## 修复路径
- **P1 换源**：从生产 checkpoint（GLM-5.3-Flash-W4A16-MTP，compressed-tensors g128 对称，178G）转换专家权重——**零量化误差**（gptq_marlin_repack + marlin_permute_scales，生产启动每次都在跑同款）→ 接受率恢复（生产 mean_draft_tokens_per_step=6.852 证明 drafter 与 g128 权重兼容）→ dense 仍用 affine checkpoint（混合合理：都是同一 bf16 模型的量化）。保留 serial/coding/prose 收益 + 17GB 内存。
- **P2 内核补丁**：decode.cu 加 `if (e0 < 0) continue;` 早退 + decode 路由改**固定 289 块布局**（每 expert 固定块号 → tile index 确定 → 累加顺序跨 R 一致 → drafted==serial）→ 从 vllm-src 重建 .so。prefill 保持动态布局（两路径同 chunk 行数，自洽）。
- **P3 放弃 C7a**：回 affine 栈走 C8 深草稿。
